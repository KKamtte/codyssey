## JSONL
- 한 줄 = JSON 하나(UTF-8). 한 줄씩 읽으면 되므로 [[python-generator-streaming]]과 잘 맞고, 숫자·목록 같은 타입이 CSV 와 달리 그대로 남는다.

## 추가는 append, 수정·삭제는 전체 다시 쓰기
- **추가**: 파일 끝에 한 줄 덧붙이면 끝. 기존 내용을 건드리지 않는다.
- **수정·삭제**: 줄 길이가 다르므로(`9000` → `12000`이면 한 글자 늘어남) 중간 한 줄만 고칠 수 없다. 뒤를 전부 밀어야 하므로 결국 전체를 새로 쓴다.

## 원자적 교체: 임시 파일 + os.replace
```python
fd, tmp = tempfile.mkstemp(dir=path.parent)      # 같은 폴더에 임시 파일
with os.fdopen(fd, "w", encoding="utf-8") as f:
    for record in records: f.write(json.dumps(record) + "\n")
    f.flush(); os.fsync(f.fileno())              # 디스크에 실제로 쓰일 때까지 기다림
os.replace(tmp, path)                            # 같은 폴더 안 rename 은 한 번에 일어난다
```
- 원본에 바로 `open(path, "w")`로 쓰다 죽으면 반쯤 쓴 파일만 남는다.
- 위 방식은 중간에 죽어도 **원본 그대로이거나 완전히 새 파일**, 둘 중 하나다. 실패하면 임시 파일만 지운다.
- 같은 폴더여야 한다: 다른 파일 시스템으로의 rename 은 원자적이지 않다.
- `mkstemp`는 권한 0600 으로 만들므로, 교체 전에 원래 파일 권한을 옮겨 준다(리뷰에서 발견).
- 바뀐 게 0건이면 교체하지 않는다. 그래서 "한 번 훑으며 임시 파일에 쓰고, 다 쓴 뒤 교체할지 정하는" 구조로 만들었다(`rewrite(records, keep=...)`).

## 파일이 깨졌을 때
- 마지막 줄에 줄바꿈이 없는 파일(편집기로 고쳤거나 이전 쓰기가 끊김)에 그대로 append 하면 두 줄이 하나로 붙어 깨진다 → 붙이기 전에 마지막 바이트를 확인해 줄바꿈을 채운다.
- 읽다가 JSON 이 아니거나 필드가 빠진 줄을 만나면 "transactions.jsonl 3번째 줄"처럼 **위치를 알려 주는 파일 오류**(종료 코드 3)로 끝낸다. 입력 오류(종료 코드 1)와 구분하는 이유는 [[python-decorator-cross-cutting]].

## 같은 생각을 다른 데서도
- CSV export 도 임시 파일에 쓴 뒤 바꿔 끼워, 반쯤 쓴 CSV 가 남지 않게 했다.
- 여러 파일을 고칠 때(카테고리를 옮기며 삭제)는 순서를 정한다: 거래를 먼저 옮기고 카테고리를 마지막에 지운다. 중간에 멈춰도 "없는 카테고리를 가리키는 거래"가 생기지 않는다.
