## 결정 사항

| # | 항목 | 상태 |
|---|---|---|
| 1 | 서비스 주제(핵심 데이터 한 종류) | **결정 (11/17, 10/27 안 변경)**: **문답 카드**. 동료 평가 대비 질문과 내 답을 카드로 관리. 핵심 데이터는 카드(질문, 답 마크다운, 분야=과제 코드, 숙련도 모름/애매/앎, 작성자, 생성·수정일). 시드는 B1-1 push 전 문답([[b1-1-review-qa]]). 이유: 앱이 데이터의 원천이 되고, 지금 하는 push 전 문답([[review-quiz]])과 바로 이어져 실제로 쓸 수 있음. **10/27 안(학습 위키 뷰어/에디터)은 버림**: 레포 `wiki/`가 원천인데 앱은 Supabase 사본이라 서로 반영되지 않고(원천 두 개), 레포에 쓰려면 GitHub 쓰기 토큰이 브라우저에 노출돼 서버 없이는 불가. LLM 호출은 넣지 않음(키 노출, AI는 B3-2) |
| 2 | 백엔드: Supabase / Firebase | **결정 (10/27)**: Supabase. 이유: 테이블 하나로 CRUD가 단순하고(SQL로 구조가 보임), Auth를 붙이기 쉬움. 계정 생성·프로젝트 만들기는 사용자가 직접 (a-4). 무료 플랜은 7일 동안 요청이 없으면 프로젝트가 일시 정지되므로 평가 요청 전에 대시보드에서 상태 확인 |
| 3 | 빌드 도구·언어: Vite + JavaScript / TypeScript | **결정 (10/27)**: Vite + JavaScript, React 19, React Router 7. 이유: 설명할 범위를 React에 집중, TS는 가산점 없음. `create-vite@9.3.2`가 템플릿 누락으로 실패해 같은 구성을 직접 만듦(파일 5개라 구조 설명에도 유리) |
| 4 | 스타일링 방식 | **결정 (11/17)**: CSS Modules(`*.module.css`) + 전역 CSS 변수(`src/styles/global.css`). 이유: 컴포넌트마다 스타일 파일을 둬 컴포넌트 분리 기준과 같은 단위로 관리되고 클래스 이름이 충돌하지 않음. Vite 기본 지원이라 설치 없음. 색·간격은 B1-1처럼 CSS 변수 |
| 5 | 보너스 범위 | **결정 (11/17)**: 무료 범위에서 셋 다. ① Supabase Auth(이메일·비밀번호) + 보호 라우트(`/cards/new`, `/cards/:id/edit`) ② 전역 상태: `AuthContext`(로그인 사용자), `ToastContext`(저장·삭제 알림) ③ 메모이제이션: 필터·검색 결과 `useMemo`, 마크다운 미리보기 `useMemo`, 목록 항목 `React.memo`. 이유: 배포 URL이 공개라 로그인 없이는 누구나 내 카드를 지울 수 있어 Auth가 실제로 필요하고, 나머지 둘은 Auth·필터와 자연스럽게 이어짐 |
| 6 | 배포 플랫폼: Vercel / Netlify | **결정 (11/17)**: Vercel(Hobby, 무료). Root Directory를 과제 폴더로, `vercel.json` rewrite로 SPA 새로고침 404 해결, 대시보드에 `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY` 등록. 이유: GitHub 연결·환경변수 설정이 단순. 계정 연결은 사용자가 직접 |
| 7 | 루트 `.gitignore`의 `lib/` (Python 템플릿) | **결정 (10/27)**: 과제 폴더 `.gitignore`에 `!src/lib/` 예외. 이유: 루트 규칙은 Python 과제에 필요하고, 영향은 이 과제 폴더 안으로 한정 |
| 8 | 라우트 | **결정 (11/17)**: `/` 홈(숙련도별 개수 요약), `/cards` 목록, `/cards/:id` 상세, `/cards/new` 등록, `/cards/:id/edit` 수정, `/login` 로그인·회원가입, `*` Not Found. 7개로 기준(5개) 충족, 목록·상세 포함 |
| 9 | 상태 → 렌더링 지점 | **결정 (11/17)**: ① 분야·숙련도 필터와 검색어 → 목록 ② 답 입력 → 마크다운 미리보기 ③ 저장·삭제 성공 → 토스트 알림 ④ 상세의 답 가리기/보기 토글 → 답 표시. 기준(3곳) 이상 |
| 10 | 권한(누가 무엇을) | **결정 (11/17)**: 조회는 누구나, 등록은 로그인 사용자, 수정·삭제는 작성자 본인만. Supabase RLS 정책으로 강제(`user_id = auth.uid()`). 회원가입은 열어 두고 **이메일 확인은 끔**. 이유: 평가자가 배포 URL에서 직접 가입해 등록/수정/삭제를 모두 확인할 수 있어야 하고, 무료 플랜 기본 메일 발송은 시간당 몇 통으로 제한됨. anon key는 원래 공개용이라 보호는 RLS가 맡음 |
| 11 | 마크다운 렌더링 | **결정 (11/17)**: `react-markdown`(npm, 무료). 이유: HTML 문자열을 `dangerouslySetInnerHTML`로 넣지 않아 B1-1에서 다룬 XSS 문제가 생기지 않음. 라이브러리 사용은 학칙의 "다른 사람 코드 가져다 쓰기"와 다름(React와 같은 공개 패키지 의존성) |
