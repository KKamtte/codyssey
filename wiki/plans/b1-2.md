## 결정 사항

| # | 항목 | 상태 |
|---|---|---|
| 1 | 서비스 주제(핵심 데이터 한 종류) | **결정 (10/27)**: 내 학습 위키([[llm-wiki]]) 뷰어/에디터. 핵심 데이터는 위키 페이지(제목, slug, 종류 concept/entity/source/analysis, 마크다운 본문, 수정일). 종류 필터·검색 → 목록, 본문 입력 → 미리보기, 저장 성공 → 알림으로 상태→렌더링 지점 3곳. `[[slug]]`는 본문에서 찾아 링크로만 바꾸고 관계 테이블은 만들지 않음. 레포 위키 페이지를 시드 데이터로. **LLM 호출은 넣지 않음**: 브라우저에서 부르면 키가 노출되고 숨기려면 서버가 필요해 과제 제약과 충돌, AI 기능은 B3-2(AI API)에서. 이유: 단일 데이터 CRUD에 딱 맞고, 내 맥락이 분명해 평가 때 설명하기 좋음 |
| 2 | 백엔드: Supabase / Firebase | **결정 (10/27)**: Supabase. 이유: 테이블 하나로 CRUD가 단순하고(SQL로 구조가 보임), 보너스 Auth를 붙이기 쉬움. 계정 생성·프로젝트 만들기는 사용자가 직접 (a-4) |
| 3 | 빌드 도구·언어: Vite + JavaScript / TypeScript | **결정 (10/27)**: Vite + JavaScript, React 19, React Router 7. 이유: 설명할 범위를 React에 집중, TS는 가산점 없음. `create-vite@9.3.2`가 템플릿 누락으로 실패해 같은 구성을 직접 만듦(파일 5개라 구조 설명에도 유리) |
| 4 | 스타일링 방식 | 미정 (a-3 전). 기본값 후보: 순수 CSS 또는 CSS Modules (B1-1에서 쓴 CSS 변수 방식 이어가기) |
| 5 | 보너스 범위 | 미정 (a-8 전) |
| 6 | 배포 플랫폼: Vercel / Netlify | 미정 (a-9 전). B1-1의 GitHub Pages는 SPA 라우팅(새로고침 404)과 환경변수 처리 때문에 맞지 않을 수 있음. 계정 연결은 사용자가 직접 |
| 7 | 루트 `.gitignore`의 `lib/` (Python 템플릿) | **결정 (10/27)**: 과제 폴더 `.gitignore`에 `!src/lib/` 예외. 이유: 루트 규칙은 Python 과제에 필요하고, 영향은 이 과제 폴더 안으로 한정 |
