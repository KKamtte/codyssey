[[b2-1]] 미션을 `main`에 merge하기 전 문답. 방식은 [[review-quiz]]. Q1~Q5는 미션 "과제 목표" 5개(계층, 제너레이터, 파일 저장, 데코레이터, 타입 힌트), Q6~Q8은 dataclass·반복 내역·오류 처리.
결과: 8문항 모두 통과. Q1·Q2는 꼬리 질문으로 설명을 구체화함.

## Q1. 계층을 나눈 이유 (통과)
- 질문: "등록된 카테고리만 허용" 규칙은 어느 계층에 있나, CLI(`cmd_add`)에 두면 무엇이 문제인가.
- 내 답: 서비스. CLI에 두면 서비스 로직이 다른 계층에 종속된다.
- 꼬리 Q1-1 답: CSV import 로 `hobby`가 그대로 저장되고, 막으려면 여러 곳에 복사해야 해서 고치다 빠뜨릴 위험. (정답)
- 보충: 규칙을 서비스 한 곳에 두면 add·import·recurring apply 가 같은 함수를 지나간다.

## Q2. 제너레이터와 heapq.nlargest (통과)
- 내 답: 리스트로 돌려주면 100만 건이 메모리에 다 올라간다. nlargest 는 힙에 N건만 유지. (정답)
- 꼬리 Q2-1 답: 새 거래는 힙의 가장 오래된 것(루트)과만 비교하고, 더 최신이면 빼고 넣는다. (정답)

## Q3. 전체 다시 쓰기와 원자적 교체 (통과)
- 내 답: 줄 길이가 달라 그 줄만 못 고친다. 원본에 바로 쓰다 죽으면 반쯤 깨지고, 임시 파일 + `os.replace`면 원본 그대로. (정답)
- 보충: 같은 길이면 덮어쓸 수도 있지만 길이가 바뀌면 뒤를 모두 밀어야 하므로 전체를 새로 쓰는 게 단순하고 안전하다.

## Q4. 데코레이터 순서 (통과)
- 내 답: 순서를 바꾸면 예외가 `log_execution`을 그냥 지나가 로그가 안 남는다. 데코레이터가 없으면 명령마다 try/except 와 로그 코드를 반복. (정답)
- 보충: 화면 출력·종료 코드는 그대로라 로그만 조용히 사라지는, 찾기 어려운 버그가 된다 (테스트 `test_03`이 지킴).

## Q5. 타입 힌트 `Callable[[Transaction], Transaction | None]` (통과)
- 내 답: Transaction 을 받아 Transaction 이나 None 을 돌려주는 함수, None 이면 삭제. 실행 때는 막지 않는다. (정답)
- 보충: 이점은 계약이 보이는 것과, 에디터·mypy 가 실행 전에 잘못된 호출을 알려 주는 것.

## Q6. frozen dataclass 와 `replace` (통과)
- 내 답: 값을 바꾸면 `FrozenInstanceError`, `replace`는 새 객체를 만든다, old 가 남아 "전 → 후"를 출력할 수 있다. (정답)

## Q7. 반복 내역 중복 방지 (통과)
- 내 답: `recurring_id`로 판단. 날짜·카테고리·금액으로 판단하면 직접 add 한 거래도 이미 만든 것으로 착각한다. (정답)
- 보충: 반대로 만든 거래의 금액을 update 하면 못 찾아서 또 만든다. `recurring_id`는 두 경우 모두 막는다.

## Q8. 파일 내용 오류를 ValueError 로 바꾸는 이유 (통과)
- 내 답: 파일 오류는 데이터를 고쳐야 하고, 그대로 두면 입력 오류로 착각한다. (정답)
- 보충: 아무것도 입력하지 않은 `list`에서 "날짜 형식이 올바르지 않습니다 / 예: 2024-01-15"가 나오고 줄 번호도 없다. 오류 종류를 원인이 있는 곳(입력 vs 파일)에 맞춘다.
